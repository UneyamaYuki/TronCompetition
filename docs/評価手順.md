# 評価手順

## 1. 評価の目的

本手順では、EK-RA8P1上で動作するメインアプリ（`app/`）が、水槽内の金魚映像から金魚の検出、餌候補の沈下、金魚への接近および餌候補の消失を確認し、給餌行動を判定できることを評価する。

評価者が金魚を用意する必要はない。開発者がiPhoneで撮影した評価用動画をリポジトリに登録し、その動画を再生した画面を評価ボードのOV5640カメラで撮影する。したがって、評価用動画は実機のカメラへ入力するための素材であり、アプリケーションが動画ファイルを直接読み込む方式ではない。

## 2. 評価対象と対象外

### 2.1 評価対象

評価対象は、リポジトリの`app/`ディレクトリにあるメインアプリのみとする。具体的には、次の処理をEK-RA8P1実機上で確認する。

- OV5640からのカメラ画像取得
- 640x480画素の画像からの金魚検出
- Ethos-U55 NPUによる金魚ボックス推論
- Cortex-M85 CPUによる餌候補の画像処理と追跡
- 金魚と餌候補の位置関係に基づく給餌判定
- 給餌完了時刻の更新と給餌空白期間の判定
- LCDへの検出状態、給餌完了、`unknown`および未給餌アラートの表示

### 2.2 評価対象外

`data_collector/`および`model/`は評価対象外である。これらをビルド、実行または評価結果の根拠として使用しない。

- `data_collector/`: 学習用画像や給餌イベントを収集するための別ファームウェアであり、実運用の給餌判定を行わない。
- `model/`: 金魚検出モデルの学習、変換およびPC上でのオフライン検証に使用する開発用コードであり、実機評価の入力経路ではない。
- PC上でのモデル精度、データセット分割、学習時間および変換時間: 本手順の評価結果には含めない。

評価者は、リポジトリを取得した後、`app/`だけを対象にビルドおよび書き込みを行う。`data_collector/`や`model/`のREADMEに記載されたコマンドを実行する必要はない。

## 3. 評価用動画の準備

### 3.1 動画の格納場所

評価用動画は、リポジトリ内の`docs/evaluation_videos/`に格納する。動画ファイルは本手順書と同じリビジョンで管理し、評価者が取得したリポジトリだけで入力素材を確認できるようにする。

ファイル名は、内容を判別できるように次の形式を推奨する。

```text
docs/evaluation_videos/feeding_01.mp4
docs/evaluation_videos/feeding_02.mp4
docs/evaluation_videos/normal_01.mp4
```

拡張子は、iPhoneから書き出した形式に応じて`.mp4`または`.mov`としてよい。評価者は格納されている動画をすべて確認し、評価時は1本ずつ使用する。

### 3.2 撮影内容

動画は2本または3本を用意する。給餌の有無を比較できるよう、次の構成を基本とする。

1. 給餌前から餌の投入、餌の沈下、金魚の接近、餌の消失までを含む給餌動画を1本以上用意する。
2. 給餌を行わず、金魚が通常遊泳する動画を1本用意する。
3. 可能であれば、餌が底面に残る、金魚が餌を隠す、照明や反射が変化するなど、判定が難しい動画を1本追加する。

給餌動画では、餌の投入前後が途切れないように撮影する。カメラは水槽へ向け、金魚が画角内に存在する状態を基本とする。人物の顔や生活空間は撮影せず、水槽内を主な被写体とする。撮影中は、カメラの移動、ズーム、極端な明るさ変更および動画速度の変更を避ける。

動画は、実機が処理する映像条件と大きく異ならないよう、通常速度で再生できる状態でリポジトリへ登録する。動画の編集で餌の沈下速度を変えたり、給餌完了に見えるように場面を切り貼りしたりしない。評価者が実際に確認できるよう、元動画の撮影内容と期待する結果を評価記録に記載する。

## 4. 評価環境

### 4.1 必要な機材

- EK-RA8P1評価ボード
- OV5640カメラモジュール
- 評価ボードに接続できるLCD
- 評価ボードへプログラムを書き込むためのJ-Link接続
- Windows PC
- 評価用動画を再生するiPhoneまたはPCディスプレイ
- 評価ボードへの電源およびUSBケーブル

### 4.2 配置

OV5640を、動画を再生するiPhoneまたはディスプレイへ向ける。再生画面には水槽内の動画だけが表示されるようにし、動画の周囲に別の映像や大きな操作パネルを表示しない。画面とカメラが正対するように配置し、画面の反射、ちらつき、明るさの自動変更およびスリープが起きないようにする。

評価中は、カメラと再生画面の距離、角度、画面輝度および動画の再生倍率を動画ごとに変更しない。動画を直接カメラへ見せるため、再生画面の状態が実機への入力条件になる。

## 5. `app/`のビルド

### 5.1 ビルド対象の確認

評価者はリポジトリのルートではなく、メインアプリのプロジェクトとして`app/`を開く。ビルド対象は`app/Debug/`のDebug構成とし、生成物として`app/Debug/app.elf`が作成されることを確認する。

`app/.vscode/tasks.json`には、メインアプリ専用の`Build app (Debug)`タスクが登録されている。このタスクを使用できる環境では、VS Codeで`app/`を開き、コマンドパレットから`Tasks: Run Build Task`を実行する。Arm GNU ToolchainとMinGWのインストール先がリポジトリの設定と異なる場合は、タスクのツールチェーンパスだけを評価環境に合わせて変更する。

### 5.2 コマンドによるビルド

コマンドでビルドする場合は、PowerShellで次のように`app/Debug/`をビルドする。`ARM_TOOLCHAIN_BIN`と`MINGW_BIN`は、評価環境にインストールされている各ツールの`bin`ディレクトリへ置き換える。

```powershell
Set-Location .\app
$env:PATH = "$ARM_TOOLCHAIN_BIN;$MINGW_BIN;$env:PATH"
$env:CPATH = "$(Resolve-Path .\ra\fsp\src\r_mipi_csi);$(Resolve-Path .\ra\fsp\src\r_vin)"
& "$MINGW_BIN\mingw32-make.exe" -C Debug -j1 all
```

ビルドが成功した場合は、`app/Debug/app.elf`が生成される。ビルドエラーが発生した場合は、`data_collector/`や`model/`をビルドして解決しようとせず、Arm GNU Toolchain、MinGW、`CPATH`および`app/Debug/`の設定を確認する。

## 6. `app/`の書き込みと起動

1. EK-RA8P1、OV5640、LCDおよびJ-Linkを接続し、評価ボードへ電源を投入する。
2. e2 studioで`app/`プロジェクトを開く。
3. `app Debug_Flat`の起動構成を選択する。この構成は`app/Debug/app.elf`を対象とし、J-Link経由でR7KA8P1KFのCPU0へ接続する。
4. RunまたはDebugを開始し、ビルド済みの`app.elf`を評価ボードへ書き込む。
5. 書き込み後にボードをリセットし、アプリケーションを再起動する。
6. LCDにカメラ映像または初期化状態が表示され、カメラ初期化が完了するまで待つ。

起動構成により自動ビルドが実行される場合でも、書き込む対象が`app/Debug/app.elf`であることを確認する。`data_collector`用の起動構成、学習済みモデルを作り直すためのコマンドおよびPC上の推論プログラムは使用しない。

## 7. 動画ごとの評価手順

動画間で状態を持ち越さないため、次の手順を動画1本ごとに繰り返す。

1. 評価対象の動画を1本選び、ファイル名と動画内容を評価記録に記入する。
2. EK-RA8P1をリセットし、アプリケーションの初期化が完了するまで待つ。
3. 動画再生画面をOV5640の画角内に配置し、カメラ映像上で水槽内の映像が確認できることを確認する。
4. 動画を先頭から通常速度で再生する。途中で一時停止、早送り、巻き戻しまたはループ再生は行わない。
5. LCD上の金魚ボックス、検出状態および給餌判定の表示を観察する。必要に応じてデバッグコンソールのログも記録する。
6. 動画終了後、給餌完了の有無、`unknown`への遷移、誤った給餌完了の有無および表示された状態を評価記録へ記入する。
7. 次の動画を評価する前に、必ずボードをリセットして状態を初期化する。

### 7.1 給餌動画で確認すること

給餌動画では、次の順序で状態が進むことを確認する。

```text
餌候補の出現
	-> 下方向への沈下軌跡
	-> 金魚への接近
	-> 金魚近傍での餌候補の消失
	-> 一定時間の非再出現
	-> FEEDING_COMPLETED
```

金魚が餌候補へ近づいただけでは給餌完了としてはならない。餌候補の沈下軌跡、金魚近傍での消失および消失後の非再出現が確認できた場合に、給餌完了時刻が更新されることを確認する。

### 7.2 通常遊泳動画で確認すること

通常遊泳動画では、金魚の移動だけで`FEEDING_COMPLETED`へ遷移しないことを確認する。餌候補の沈下軌跡がない状態で給餌完了時刻が更新された場合は誤検出として記録する。

### 7.3 判定が難しい動画で確認すること

餌が底面に残った場合、金魚に隠れた餌が再出現した場合、カメラ振動や照明変化で画面全体の差分が増えた場合は、給餌完了と断定せず`unknown`として扱うことを確認する。`unknown`の場合、最後に確認した給餌時刻を更新してはならない。

## 8. 給餌空白期間の評価

給餌完了時刻が記録された後、最後の給餌からの経過時間が表示または管理されることを確認する。本番設定では3日間給餌完了が確認されない場合に未給餌アラートとなるが、評価時は待ち時間を短縮するため、テスト設定の10分間を使用する。

1. 給餌動画で`FEEDING_COMPLETED`が成立した時刻を記録する。
2. 以後、給餌動画を再生せずに監視を継続する。
3. 10分間給餌完了が記録されない状態を維持する。
4. LCDに未給餌アラートが表示されることを確認する。
5. `unknown`が発生した場合、それだけで給餌完了時刻が更新されたり、未給餌アラートが解除されたりしないことを確認する。

時刻が未設定または無効な場合は、未給餌と断定せず、監視時刻不明として扱うことを確認する。実機の電源断や再起動を含む評価を行う場合は、再起動後に最後の給餌時刻が不正に初期化されないことも記録する。

## 9. 評価結果の記録

動画1本につき、最低限次の項目を記録する。

| 項目 | 記録内容 |
|------|----------|
| 動画ファイル | 例: `feeding_01.mp4` |
| 動画の種類 | 給餌、通常遊泳、判定困難 |
| 実機入力 | OV5640で再生画面を撮影したこと |
| 金魚検出 | 検出できた、見失った、`unknown` |
| 餌の沈下追跡 | 成立した、成立しなかった |
| 給餌判定 | `FEEDING_COMPLETED`、`unknown`、未判定 |
| 給餌時刻 | 更新された時刻または更新なし |
| 未給餌アラート | 表示された、表示されなかった、対象外 |
| 結果 | 合格、不合格、追加確認 |
| 備考 | 反射、画面ちらつき、カメラずれなど |

給餌動画で完了が確認できない場合でも、餌が底面に残った、金魚に隠れた、再生画面の反射が強かったなど、判定不能となった理由を記録する。`unknown`を未給餌の成功として扱わず、給餌完了の見逃しと判定不能を分けて評価する。

## 10. 評価時の注意事項

- 評価対象は`app/`だけであり、`data_collector/`と`model/`は評価対象外である。
- 評価用動画はPC上で直接推論させず、再生画面をOV5640で撮影して実機入力とする。
- 動画ごとにボードをリセットし、前の動画の給餌状態や時刻を持ち越さない。
- 動画は通常速度で再生し、評価中に再生速度や画角を変更しない。
- カメラを人へ向けず、水槽内の映像だけを評価対象とする。
- `unknown`は給餌完了ではなく、画像から判定できない状態として記録する。
- 外部通知（Wi-Fi、BLEなど）は今回の評価対象に含めない。評価対象は実機LCD上の状態表示までとする。
